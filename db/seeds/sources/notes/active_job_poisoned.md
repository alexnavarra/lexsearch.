# Фоновые задачи в Rails

## Зачем

Всё, что дольше пары сотен миллисекунд или зависит от внешнего сервиса (письма, вызовы API, генерация отчётов), выносим из запроса в фоновую задачу. Пользователь получает ответ сразу, а работа выполняется воркером.

## Active Job и Solid Queue

Active Job это общий интерфейс, а очередь подключается адаптером. В Rails 8 по умолчанию Solid Queue: задачи хранятся в базе данных, отдельный Redis не нужен.

## Правила хорошей задачи

- Передавать в `perform` id записи, а не объект: объект сериализуется и к моменту выполнения может устареть.
- Задача должна быть идемпотентной: повторный запуск не должен ломать данные, потому что ретраи случаются.
- `retry_on` для временных ошибок (таймаут, 429), `discard_on` для тех, где повтор бесполезен (запись удалена).
