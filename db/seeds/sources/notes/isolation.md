# Уровни изоляции транзакций

## Аномалии

**Грязное чтение**: транзакция видит изменения другой транзакции, которая ещё не зафиксирована. В PostgreSQL невозможно ни на каком уровне.

**Неповторяемое чтение**: одна и та же строка, прочитанная дважды внутри транзакции, возвращает разные значения, потому что между чтениями другая транзакция её изменила и зафиксировала.

**Фантомное чтение**: повторный запрос с тем же условием возвращает другой набор строк, потому что кто-то вставил или удалил подходящие строки.

**Аномалия сериализации**: результат параллельных транзакций не совпадает ни с одним порядком их последовательного выполнения. Классический пример: write skew, когда два врача одновременно снимают себя с дежурства, каждый видит, что второй ещё дежурит, и в итоге не дежурит никто.

## Уровни в PostgreSQL

| Уровень | Что видит запрос | Что возможно |
| --- | --- | --- |
| Read Committed (по умолчанию) | снимок на начало **каждого запроса** | неповторяемое и фантомное чтение |
| Repeatable Read | снимок на начало **транзакции** | аномалия сериализации; при конфликте записи ошибка `could not serialize access` |
| Serializable | как Repeatable Read плюс отслеживание зависимостей (SSI) | ничего; при опасном пересечении одна транзакция откатывается |

Read Uncommitted в PostgreSQL ведёт себя как Read Committed.

## Что говорить на собеседовании

- PostgreSQL реализует изоляцию через MVCC: читатели не блокируют писателей, каждая транзакция видит свой снимок данных.
- На Repeatable Read и Serializable приложение **обязано** уметь повторять транзакцию при ошибке сериализации (SQLSTATE `40001`).
- В Rails: `ActiveRecord::Base.transaction(isolation: :serializable) { ... }` и `retry` на `ActiveRecord::SerializationFailure`.
- Чтобы не поднимать уровень изоляции ради одной строки, хватает `SELECT ... FOR UPDATE` (в Rails `lock` или `with_lock`).
